宏月（LunaMacro）情感系统重构 · 架构蓝图

目标版本：0.9.15（versionCode 113） 状态：草案，待评审 编写依据：2026-11-11 对 NexusAgent 主干（0.9.14 / v8 数据库）的实地通读 一句话：把情绪从「三档标签 + 好感度数字」改成 PAD 连续坐标 + 快慢双层 + 情感调制的记忆召回 + 会话日记，让她的状态成为记忆的一部分，而不是每轮重新猜的一层面具。

0. 摘要

现在的她是这样运转的：用户说一句话 → 关键词表判出「被夸 / 被凶 / 普通」 → 好感度进位、心情写成一个中文字符串 → 下一轮把「当前心情：开心」塞进提示词。

三个结构性缺陷：

  1. 情绪只有三个值，且和关系进度（好感度）绑在一起，无法表达「强颜欢笑」这种人类常态。
  2. 记忆完全不带情绪。10 条事实按权重平铺进提示词，她难过时和开心时看到的是同一份东西，所以是「情感失忆」。
  3. 每次冷启动都是白纸。除了聊天历史和摘要，没有任何「我昨天到睡前是什么心情、有哪句话没说完」的痕迹。

本次重构分三块，互相咬合但可以独立上线：

块 内容 解决的问题
一 PAD 三维状态 + 快慢双速动力学 情绪不再是标签，而是坐标；能表达表里不一
二 记忆的情感指纹 + 自适应检索打分 情绪一致性召回，强度高的记忆更难忘
三 会话级情感快照（日记） 冷启动不再失忆

全部改动不引入新模型、不引入 embedding、不每轮多调一次 LLM，成本增量只有「每天一次的日记生成」。

1. 先纠正一处错位（重要）

需求里写的是「修改 MemoryRouter 的检索评分算法，引入情感一致性权重」。

MemoryRouter 不是叙事记忆的检索器。 它是一个任务自动化的动作回放路由器（412 行，memory/ 包），职责是：拿当前界面指纹（包名 + UI 节点 hash）和意图键去匹配 ActionMemory，命中就跳过 LLM 直接点屏幕（Muscle 级），没命中就注入避坑经验（Enhanced 级）或走老路（Cold 级）。

如果把「当前 PAD 与记忆编码 PAD 的匹配度」塞进它的评分：

  • 两条本该命中的动作记忆会因为「此刻心情不对」被拒绝回放 → 任务失败率上升，而用户完全不知道原因；
  • 它也不解决用户真正抱怨的「情感失忆」——那是长期对话记忆的事。

结论：MemoryRouter / ActionMemory / MemoryReplay / MemoryConsolidator 本次一行不改。 动作回放必须保持确定性，这是它存在的全部价值。

情感调制的目标锁定在叙事记忆：long_term_memory（MemoryEntity）与 FlexiMem.recall。

逐条核过，不照抄需求里的转述：

关于 Sentipolis 的 120 分钟半衰期：它的模拟世界是 20 分钟走一步、共 36 步（12 小时），120 分钟相当于「六步」。我们是真实对话节奏（一轮几秒到几分钟，然后可能几小时不说话），直接照搬 120 分钟等于「她记仇两小时」，偏钝。本方案取 20 分钟半衰期，并在第 12 节列为可调参数。

5. 块一：PAD 连续表征与双速动力学

5.1 数据结构

新文件 app/src/main/java/com/nexus/agent/persona/PadState.kt。

kotlin
/** PAD 三维坐标，各轴 [-1, 1]。0 表示中性。 */
data class PAD(val p: Float, val a: Float, val d: Float) {
    fun clamp(): PAD
    fun length(): Float                 // 0 ~ √3，即情绪强度
    fun dist(o: PAD): Float             // 0 ~ 2√3，用于情绪一致性
    operator fun plus(o: PAD): PAD
    operator fun minus(o: PAD): PAD
    operator fun times(k: Float): PAD
    companion object { val ZERO = PAD(0f, 0f, 0f) }
}

八分区按 Mehrabian 标准表（单测逐条钉死，不能凭印象）：

P A D 英文 中文
+ + + Exuberant 雀跃
+ + − Dependent 依恋
+ − + Relaxed 松弛
+ − − Docile 温顺
− + + Disdainful 轻蔑
− + − Anxious 焦躁
− − + Hostile 敌意
− − − Bored 消沉

强度三档（照 ALMA）：length < 0.25 → 「淡淡的」；0.25 ~ 0.60 → 不加修饰；> 0.60 → 「很」。

5.2 双速更新

text
快变量 quick：本轮的情绪波动
  ① 每轮开始先按经过时间衰减回基线：v ← v + (base − v) × (1 − 2^(−Δt/20min))
  ② 叠加本轮 appraisal delta（模长封顶 0.6）
  ③ 结果 clamp 到 [-1,1]³

慢变量 slow：长期基调
  ① 只有 quick.length() ≥ 0.25 才推（闲聊不推，否则天天漂）
  ② EMA：slow ← slow + (quick − slow) × 0.08
  ③ 随时间衰减回基线，半衰期 6 小时（人睡一觉心情就淡了）

「强颜欢笑」的触发条件（在提示词层判定）：

text
sign(quick.p) ≠ sign(slow.p)  且  |quick.p − slow.p| > 0.40

判定成立时，提示词额外给一句「嘴上说没事，心里其实…」。这是本块最核心的产出——离散标签体系里根本无法表达的东西。

5.3 基线推导

用已有的三个性格维度 + 好感度近似 ALMA 的 Big Five→PAD 回归（我们没有人格五因素，用三项替代并在注释里写清这是近似）：

kotlin
fun baselineOf(extroversion: Int, sensibility: Int, rebelliousness: Int, affinity: Int): PAD {
    val e = extroversion / 100f        // 0~1
    val s = sensibility / 100f
    val r = rebelliousness / 100f
    val aff = (affinity - 50) / 50f    // -1~1
    return PAD(
        p = (0.10f * e + 0.20f * aff + 0.10f).coerceIn(-0.4f, 0.4f),
        a = (0.35f * e - 0.15f + 0.10f * s).coerceIn(-0.4f, 0.4f),
        d = (0.45f * r - 0.05f).coerceIn(-0.4f, 0.4f)
    )
}

性格外向 → 基线更活跃；感性 → 波动更大（影响 delta 倍率，见 5.4）；叛逆 → 基线支配感高；好感度高 → 底色更暖。

5.4 刺激映射（PadAppraisal.kt，纯规则）

保留现有词表（PRAISE_WORDS / COLD_WORDS / SOFT_EXCEPTIONS 原样搬过来，别重写——那些词是踩过坑调出来的），把「→ 标签」改成「→ PAD delta」：

信号 触发条件 ΔP ΔA ΔD
PRAISE 被夸 命中夸奖词表 +0.35 +0.10 +0.10
COLD 被凶 命中冷淡词表（软例外先放行） −0.45 +0.20 −0.25
RELIED 被依赖 「帮我 / 你帮我 / 帮我弄 / 靠你了」 +0.20 +0.10 +0.15
IGNORED 被晾着 距上一轮 > 6 小时（每 6 小时最多算一次，累计上限 2 次） −0.15 −0.15 −0.05
LATE_NIGHT 深夜 PresenceSense.isLateNight 且有对话 −0.05 −0.20 0
CARE_AT_NIGHT 深夜关怀 深夜 + 「睡 / 休息 / 晚安 / 别熬」 +0.20 −0.10 +0.05

三条防炸规则：

  1. 同类信号每轮只算一次（一句话里三个夸奖词不该 ×3）。
  2. 单轮 delta 总模长封顶 0.6，一句难听话不能把情绪打穿。
  3. delta 乘以感性倍率：0.7 + sensibility/100 × 0.6（感性 0 → 0.7 倍，感性 100 → 1.3 倍）。

负向惩罚仍保留原设计的 5:1 强度（被凶 −0.45 vs 被夸 +0.35，再叠加 D 轴下降带来的后续影响）。

5.5 持久化：pad_state 单行表

为什么单独建表，不进 persona_profile：saveProfile() 是低频全量覆盖（设置页改个名字就把整行写回），PAD 高频且必须连续，混在一张表里必然被误清。这是本方案里最容易踩、后果最隐蔽的坑。

kotlin
@Entity(tableName = "pad_state")
data class PadState(
    @PrimaryKey val id: Long = 1L,
    val quickP: Float = 0f, val quickA: Float = 0f, val quickD: Float = 0f,
    val slowP: Float = 0f,  val slowA: Float = 0f,  val slowD: Float = 0f,
    val baseP: Float = 0f,  val baseA: Float = 0f,  val baseD: Float = 0f,
    val updatedAt: Long = 0L,
    val lastDecayAt: Long = 0L
)

写入策略：

  • 内存持有当前 PAD（PadDynamics object），onTurn 后标脏；
  • 2 秒防抖异步落库（一轮对话里用户连发三条只写一次）；
  • 冷启动读取时，若 now − lastDecayAt 很久，先补算衰减再参与计算（否则睡一晚醒来心情还是昨晚的峰值）。

6. 块二：情感指纹与自适应记忆检索

6.1 表结构改动

long_term_memory 加 5 列，全部 NOT NULL DEFAULT，老行落成中性：

列 类型 默认 含义
padP / padA / padD REAL 0 编码时刻的情绪坐标（中性 = 0,0,0）
emotionalIntensity REAL 0 编码时的情绪强度（quick.length() / √3，0~1）
keywords TEXT '' 抽取时用规则切出的关键词，召回打分用

keywords 的来源：不重写抽取 prompt，复用 FlexiMem.extractKeywords(fact)（纯规则，零成本），落库时拼成 \u0001 分隔（沿用项目里避开逗号劈词的教训）。

6.2 打分公式（persona/MemoryRanker.kt，纯函数）

text
semantic   = 关键词重叠率            // 命中数 / max(1, min(queryK, memK))
sim_emo    = 1 − dist(curQuick, memPAD) / (2√3)     // 0~1
nowIntensity = curQuick.length() / √3               // 0~1
w_emo      = 0.15 + 0.35 × nowIntensity             // 自适应：平静 0.15 → 激烈 0.50
effectiveAge = ageMs / (1 + 0.8 × memIntensity)     // 情绪越强越难忘
recency    = exp(−effectiveAge / 30天)

score = (1 − w_emo) × semantic + w_emo × sim_emo + 0.25 × recency

硬门槛：semantic < 0.20 → 直接出局（不参与排序）

三个设计意图：

  1. 自适应权重（来自 AFT）：她平静时靠语义找记忆，情绪激烈时靠情绪找记忆。固定权重做不到这种「同一套代码、不同人格时刻」。
  2. 强度调制遗忘（来自「情绪强度越高越难忘记」）：不是给强度单独加权，而是把它揉进时间衰减的分母——语义上就是「这段记忆老得比别人慢」。
  3. 硬门槛是保命的：没有它，用户难过时她会翻出一件毫不相干的伤心事，那不是共情，是撞鬼。情绪一致性只许重排，不许凭空引入。

6.3 中性记忆不偏置（迁移兼容的关键）

老数据 pad = (0,0,0)、intensity = 0，代入公式：

  • sim_emo 对所有老记忆都是同一个值（当前情绪越强，这个值越低）；
  • 由于它是同一个常数，排序上不产生任何偏好，只是整体压缩了分差；
  • recency 正常计算。

也就是说：迁移后老记忆的相对顺序仍然由语义与时间决定，不会集体沉底或集体冒头。这一点必须写进单测（6.6 第 2 条）。

6.4 检索入口改造

现状：PersonaStore.loadMemories(limit) → MemoryDao.top(limit)。

改造：

kotlin
// MemoryDao 新增
@Query("SELECT * FROM long_term_memory ORDER BY createdAt DESC LIMIT :limit")
suspend fun recent(limit: Int): List<MemoryEntity>   // 取 200 条候选池

// PersonaStore 新增（带默认实现，FakeStore 不受影响）
fun loadMemoriesFor(query: String, pad: PAD, limit: Int, onLoaded: (List<String>) -> Unit) =
    loadMemories(limit, onLoaded)

RoomPersonaStore 覆写为：recent(200) → MemoryRanker.rank(list, query, pad, 10) → 回调。

PersonaEngine.reloadMemories() 改为带 query 与当前 PAD 的版本；异常或空结果时回退老的 top(limit)——最坏情况是「这次没排序」，不会出现空记忆。

6.5 注入文案

结构不变（还是 - 事实 列表），只改「选哪 10 条 + 顺序」。这样即使打分逻辑有偏，最坏是挑错几条，不会让提示词结构错乱。

可选微调（第二阶段再做）：给情绪强度 > 0.6 的记忆前面加一个很短的情绪标记，例如 - [那天挺难受的] 他说项目黄了。这个先不做，等打分跑稳再加——多一个字段就多一个可能被模型复述的东西。

6.6 单测清单（MemoryRankerTest）

  1. 空集、单条、全同分不崩。
  2. 中性记忆不偏置：一组老数据（pad 全 0），当前情绪任意，排序结果与纯 recency 排序一致。
  3. 情绪一致性生效：两条语义相当、时间相当的记忆，一条 P=−0.8、一条 P=+0.8，当前 P=−0.8 时前者排前。
  4. 硬门槛生效：语义 0 的记忆即便情绪完全一致也进不了 top。
  5. recency 单调：其余相同时，越新越前。
  6. 强度调制：同年龄的高强度记忆比低强度记忆排前。
  7. 自适应权重：同一个候选集，nowIntensity=0 与 =1 时 w_emo 分别落在 0.15 与 0.50 附近。

7.3 输入给模型什么

7.4 注入规则（两处必须克制）

位置：styleBlock 之后、toneBlock 之前——不是最前面。

8. 数据库迁移 v8 → v9

kotlin
val MIGRATION_8_9 = object : Migration(8, 9) {
    override fun migrate(db: SupportSQLiteDatabase) {
        // ① PAD 单行表（纯建表，不动老表）
        db.execSQL(
            "CREATE TABLE IF NOT EXISTS `pad_state` (" +
                "`id` INTEGER PRIMARY KEY NOT NULL, " +
                "`quickP` REAL NOT NULL, `quickA` REAL NOT NULL, `quickD` REAL NOT NULL, " +
                "`slowP` REAL NOT NULL, `slowA` REAL NOT NULL, `slowD` REAL NOT NULL, " +
                "`baseP` REAL NOT NULL, `baseA` REAL NOT NULL, `baseD` REAL NOT NULL, " +
                "`updatedAt` INTEGER NOT NULL, `lastDecayAt` INTEGER NOT NULL)"
        )
        // ② 长期记忆加情感指纹（全部带 DEFAULT，老行落成中性）
        db.execSQL("ALTER TABLE `long_term_memory` ADD COLUMN `padP` REAL NOT NULL DEFAULT 0")
        db.execSQL("ALTER TABLE `long_term_memory` ADD COLUMN `padA` REAL NOT NULL DEFAULT 0")
        db.execSQL("ALTER TABLE `long_term_memory` ADD COLUMN `padD` REAL NOT NULL DEFAULT 0")
        db.execSQL("ALTER TABLE `long_term_memory` ADD COLUMN `emotionalIntensity` REAL NOT NULL DEFAULT 0")
        db.execSQL("ALTER TABLE `long_term_memory` ADD COLUMN `keywords` TEXT NOT NULL DEFAULT ''")
    }
}

迁移纪律（沿用现有约定，一条都不能松）：

  • version = 9，addMigrations(...) 追加，不设 fallbackToDestructiveMigration；
  • 建表 SQL 与实体生成的 schema 逐字对齐（列顺序、NOT NULL、默认值）；
  • 出包后核对 app/schemas/…/9.json 与迁移语句是否一致；
  • pad_state 的 id 不加 AUTOINCREMENT（单行固定 id=1，加了会让 Room 的 schema 校验对不上）。

13. 明确不做

  1. 不动动作回放链路：MemoryRouter / ActionMemory / MemoryReplay / MemoryConsolidator / MemoryNightShift 的巩固逻辑，一行不改。
  2. 不引入 embedding 模型：体积、so 依赖、以及视觉链路刚刚踩过的 SIGSEGV 教训都不允许。语义分用规则关键词近似。

  5. 本轮不给 TopicSeed / InnerThought 加情感指纹：先把 MemoryEntity 这条主路跑稳，下一轮再扩。
  6. 不做「情绪驱动的主动问候」：心跳逻辑刚在 0.9.4 收敛过，这轮不碰。

B.2 与蓝图的三处偏差（都是实现时发现必须改的）

# 蓝图写的 实际落地 原因
1 pad_state 主键写 ` id INTEGER PRIMARY KEY NOT NULL ` ` id INTEGER NOT NULL, …, PRIMARY KEY(id) ` Room 对非自增整型主键生成的是表级主键约束，不是我原先以为的列级写法。两者在 SQLite 里语义等价（都是 rowid 别名、PRAGMA table_info 输出一致，迁移能过校验），但改成逐字对齐导出 schema，免得以后对照时误判漏写
2 打分复用 FlexiMem.extractKeywords MemoryRanker.tokenize 独立实现同口径 FlexiMem 是持有线程池的 object，纯 JVM 单测里不想因为切个词就拉起 Executor。注释已标明「口径漂移时以本文件为准」
3 keywords 默认值写 '' 实体侧 @ColumnInfo(defaultValue = "''")，迁移侧 DEFAULT '' Room 会拿 sqlite_master 里的默认值和实体期望值做字符串比对，两边必须逐字一致（这一条是 Room cannot verify the data integrity 最常见的成因）

C.2 跑轨迹跑出来的三处修正

写完单测全绿，但单测只能证明「公式按我写的算」。于是又写了一个临时脚本 （PadTraceTest，跑完已删）把一段「一整天」的对话喂进去，把每一步的坐标打出来看。 三处问题全是这么露出来的：

① 被晾一夜被判成「敌意」

text
隔夜 12 小时 + 凌晨 4 点开口 → 快(−0.19, −0.41, +0.08) → 敌意

IGNORED 原来是 (−0.15, −0.15, −0.05)：P/A 各掉 0.15，D 只掉 0.05，两轮叠加后 D 相对变成了「高」，八分区就给「敌意」。可「他一天没理我」不是有攻击性，是蔫 —— 她说不上话也使不上劲。改成 (−0.16, −0.14, −0.20)，D 掉得比 P 还多，落到「消沉」。

② 默认底色是「淡淡的雀跃」

baselineOf 原来有三个正/负常数项（+0.10 / −0.15 / −0.05），默认档案（三项 50、 好感 50）算出来是 (0.15, 0.075, 0.175)，长度 0.24 —— 语义上等于「她本来心情就不错」， 羁绊面板开机第一天就挂个 😄，跟「我们才刚认识」打架。常数项重写成 −0.10 / −0.175 / −0.225，让「中性性格 + 中等好感」正好落在原点（长度 0.05 < NEUTRAL_EPS）， 开机是「平静」。性格或好感度偏离原点时才显出个性底色。

③ 凌晨四点的「困」被说成「消沉」

text
被关心一句 → 快(−0.01, −0.45, −0.12) → 消沉

低唤醒是生理状态，低愉悦才是情绪低落，八分区只有后者。混了之后模型会把 「凌晨四点的困」演成「抑郁」。加第二个特例（第一个是「平静」）：A ≤ −0.30 且 P ≥ −0.20 时说「犯困」。P 也很低时（真被伤了心）仍然说「消沉」，不拿「困」糊过去。 moodLabelOf 走同一条路，所以羁绊面板会自动挂 😴。

D.2 打分实测：同一批记忆，两种心情

轨迹脚本（跑完已删）喂了四条带情感指纹的记忆，查询固定为「最近总是很累」，只换当前心情：

当前心情 排序（分数）
很雀跃 「最近总是很开心，升职了」0.86 →「最近总是很忙」0.80 →「最近总是失眠」0.79
很焦躁 「最近总是失眠，睡不着」0.87 →「最近总是很忙」0.84 →「最近总是很开心」0.78

三条的语义分完全相同（0.50），位置变化全部由情绪一致性造成 —— 这正是「开心时想起开心的事」 在数值上的样子。同一批数据换成「明天要体检」这个和它们毫无关系的查询时，命中 0 条 → 回退 top(10)， 不会硬塞一条不相干的伤心事。

D.3 日记：两处真实修正

① 兜底模板读起来像病历

第一版兜底直接拼八分区：

text
今天心里有点敌意。          ← PAD(-0.12,-0.05,0) 落进了「敌意」那一格
今天心里很焦躁。

八分区是给提示词用的分类标签，清楚但不好听。改成五档口语（Diary.moodPhraseOf）： 挺平静的 / 挺轻快的 / 挺安稳的 / 有点烦 / 有点发沉 / 有点静不下来 / 有点提不起劲， 只保留「说不上什么滋味」作兜底。改完同一组数值输出：

text
今天心里有点发沉。他还提了「明天要体检」，我没往下问。

顺带钉了一条单测：日记里永远不许出现「敌意 / 焦躁 / 消沉 / 雀跃」这类分类词。

② 中文句子之间被插了空格

模型输出是多行的，压成一段时用 " " 替换换行，得到 第一句。 第二句。—— 中文里的这个空格读起来是机翻。改成按两侧字符判断：两边都是东亚字符（码位 ≥ 0x2E80）就不补空格， 英文单词之间照旧补。这条是单测当场抓出来的（多行压成一段）。

D.4 UI 露脸

位置 长什么样
设置 → 情感 三个开关（PAD / 情感调制召回 / 会话日记），每个都带「关掉之后是什么行为」
设置 → 情感（实时读数） 此刻：雀跃 | 底色：平静（每 2 秒刷新）
羁绊卡片 独立一行：此刻：雀跃 | 底色：平静，同一行灰底小块，位置在好感度进度条下方

为什么设置页要轮询 2 秒：用户验情绪的方式就是「在聊天窗口说一句话 → 切回来看看变没变」。 轮询只在设置页可见时跑，离开即取消，代价可以忽略。

「此刻 / 底色」这两个词本身就是双速动力学的界面翻译：前者每轮都动，后者要好几天才挪一格。
